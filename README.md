# موقع Anis CH — النسخة v2 (Hardened Security Edition)

موقع كامل احترافي: HTML/CSS/JS من جهة الواجهة، و **Supabase** من جهة قاعدة
البيانات، المصادقة، التخزين، و**Edge Function** آمنة لتوليد روابط تحميل
مؤقتة. لا حاجة لأي خادم تديره بنفسك.

هذه النسخة تحتوي على **إصلاحات أمنية جوهرية** مقارنة بالنسخة الأولى —
اقرأ قسم "ما الذي تغيّر ولماذا" قبل النشر، فهو يشرح ثغرات حقيقية تم سدّها.

---

## 🚀 خطوات التفعيل (20 دقيقة، مرة واحدة فقط)

### 1) قاعدة البيانات
من لوحة Supabase: **SQL Editor → New query** → افتح `sql/shema.sql`، انسخ
محتواه كاملاً، الصقه، ثم اضغط **Run**.

> ✅ هذا السكربت **آمن للتنفيذ حتى لو كان لديك مشروع Supabase قديم يستعمل
> النسخة الأولى** — لن يحذف بياناتك، فقط يُصلح السياسات وينشئ ما ينقص.

هذا ينشئ: الجداول، صلاحيات RLS المشدّدة، دالة `is_admin()` الآمنة،
trigger منع الترقية الذاتية لصلاحية admin، جدول `download_logs`،
ويجعل bucket البرمجيات **خاصًا (private)**.

### 2) نشر Edge Function (إلزامي — بدونها لن يعمل التحميل)
التحميل الآن يمر عبر دالة خادم آمنة توقّع الروابط مؤقتًا. يجب نشرها عبر
[Supabase CLI](https://supabase.com/docs/guides/cli):

```bash
npm install -g supabase
supabase login
supabase link --project-ref VOTRE_PROJECT_REF
supabase functions deploy get-download-url
```

`VOTRE_PROJECT_REF` تجده في رابط مشروعك (الجزء بعد supabase.co/ في URL
اللوحة، أو من Project Settings → General).

لا حاجة لضبط أي مفتاح يدويًا: `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY`
و`SUPABASE_ANON_KEY` متوفرة تلقائيًا كمتغيرات بيئة لكل Edge Function في
Supabase.

### 3) انسخ مفاتيح مشروعك إلى الموقع
من **Project Settings → API**: انسخ **Project URL** و **anon public key**،
والصقهما في `js/config.js` (استبدل القيم الموجودة).

### 4) أنشئ حسابك وفعّل صلاحية المشرف
1. افتح `index.html`، اضغط "تسجيل الدخول" → أنشئ حسابًا ببريدك (كلمة مرور
   8 خانات على الأقل مع حرف ورقم).
2. فعّل بريدك عبر الرابط المُرسَل تلقائيًا من Supabase.
3. من **SQL Editor** في Supabase:
   ```sql
   update public.profiles set is_admin = true where email = 'you@example.com';
   ```
4. سجّل الدخول من جديد → ستظهر "لوحة التحكم" في قائمة حسابك.

### 5) فعّل تسجيل الدخول عبر Google / GitHub (اختياري لكن مُستحسَن)
من لوحة Supabase: **Authentication → Providers** → فعّل Google و/أو GitHub،
واتبع التعليمات هناك لإنشاء OAuth App لكل منهما (كل مزوّد يعطيك
Client ID / Client Secret تُدخلهما في نفس الصفحة). لا حاجة لأي تعديل في
كود الموقع — الأزرار جاهزة مسبقًا.

### 6) فعّل رابط "نسيت كلمة المرور" (Redirect URL)
من **Authentication → URL Configuration** أضف نطاقك (ومنفذ التطوير المحلي
إن أردت) إلى **Redirect URLs**، مثال:
```
https://votredomaine.com/index.html
http://localhost:3000/index.html
```
بدون هذه الخطوة، رابط "إعادة تعيين كلمة المرور" المُرسَل بالبريد لن يعيد
المستخدم لصفحتك بشكل صحيح.

## 📦 كيف تضيف برنامجًا جديدًا للتحميل

من `admin.html`:
1. اختر "رفع ملف" أو "رابط خارجي فقط".
2. اسحب الملف أو انقر لاختياره (حتى 200 ميغا؛ الامتدادات: apk, exe, msi,
   zip, rar, 7z, pdf, mp4, dmg, iso, jpg/png/webp...).
3. املأ الاسم والوصف (العربي إجباري، البقية اختياري).
4. اختر **مستوى الاشتراك المطلوب**: مجاني (يظهر للجميع بعد تسجيل الدخول)،
   أو Pro (فقط لمن ترقّيه يدويًا من قسم "إدارة المستخدمين")، أو Enterprise.
5. اضغط "رفع ونشر" — يظهر فورًا في الموقع.

## 💳 كيف تُرقّي مستخدمًا إلى خطة Pro (بعد الدفع يدويًا عبر واتساب/تحويل)

لا يوجد بوابة دفع إلكترونية مدمجة (Stripe/PayPal) في هذه النسخة — لم
يُطلب ذلك ولا أملك مفاتيح API لحسابك. البديل المطبَّق فعليًا وهو **شائع
جدًا لمستقلين/شركات صغيرة**:
1. الزبون يتواصل عبر واتساب أو نموذج "طلب اشتراك Pro" في الموقع، ويدفع
   يدويًا (تحويل بنكي، D17، إلخ).
2. أنت تفتح `admin.html` → قسم "إدارة المستخدمين والاشتراكات" → تبحث
   ببريده → تغيّر خطته إلى "Pro" من القائمة المنسدلة مباشرة.
3. فورًا، كل الملفات المُعلَّمة "Pro" تصبح قابلة للتحميل من حسابه (يتحقق
   من ذلك خادم Edge Function وليس فقط الواجهة، فلا يمكن التحايل عليه).

إن أردت لاحقًا بوابة دفع آلية بالكامل (Stripe مثلاً)، أخبرني في محادثة
لاحقة ومعك مفاتيح Stripe الخاصة بك، وسأدمجها بنفس مستوى الجدّية.

## 🔒 ما الذي تغيّر أمنيًا ولماذا (مهم أن تقرأه)

| المشكلة في النسخة الأولى | الخطر | الحل المطبَّق |
|---|---|---|
| `main.js` بها `import` مكسور | الموقع كله (كتالوج، معرض، نموذج تواصل) لا يعمل فعليًا في المتصفح | إعادة كتابة `main.js` بدون استيراد كسور |
| bucket البرمجيات **عام (public)** | أي شخص، حتى بدون تسجيل دخول، يقدر يسرق رابط الملف مباشرة من استجابة الـ API ويحمّله بدون المرور بأي تحقق | البucket أصبح **خاص**، والتحميل يمر إجباريًا عبر Edge Function موقَّعة، صالحة 60 ثانية فقط |
| سياسة `update` على `profiles` بلا قيود | أي مستخدم مسجَّل يقدر يمنح نفسه `is_admin = true` من كونسول المتصفح مباشرة! | trigger يمنع تغيير `is_admin`/`subscription_plan` إلا من مشرف حقيقي |
| RLS على `profiles` باستعلام يستدعي نفس الجدول | خطر recursion معروف في Postgres/Supabase | دالة `is_admin()` مركزية بصلاحية `security definer` |
| لا سياسة `UPDATE` على `contact_messages` | زر "تعليم كمقروء" في اللوحة لم يكن يعمل فعليًا | سياسة `contact_update_admin` مضافة |
| روابط `file_url`/`external_url`/`media_url` تُدرج بدون تهريب كامل | ثغرة XSS محتملة عبر كسر خاصية HTML أو حقن `javascript:` | `escapeAttr()` + `isSafeUrl()` على كل رابط قادم من قاعدة البيانات |
| رسائل خطأ تسجيل الدخول تكشف تفاصيل | تسريب معلومة "هل هذا البريد مسجَّل؟" (user enumeration) | رسائل خطأ عامة موحّدة |
| لا يوجد "نسيت كلمة المرور" | مستخدم يفقد الوصول لحسابه نهائيًا | تدفق كامل عبر `resetPasswordForEmail` + `updateUser` |
| لا حد أدنى لقوة كلمة المرور | حسابات سهلة الاختراق | 8 خانات + حرف + رقم إجباري |
| لا CSP ولا رؤوس أمان | نافذة أوسع لهجمات XSS/clickjacking | `Content-Security-Policy` + `Referrer-Policy` عبر meta |
| لا honeypot في نموذج التواصل | سبام آلي عبر بوتات | حقل مخفي يكتشف البوتات تلقائيًا |

**ملاحظة صادقة (لا أخفي عليك شيئًا):** الـ `anon key` الظاهر في
`js/config.js` هو **مصمَّم ليكون علنيًا** (نفس فلسفة Firebase) — الحماية
الحقيقية هي سياسات RLS في قاعدة البيانات، وقد شُدِّدت جميعها. أما
`service_role key` (المفتاح الخطير الذي يتجاوز كل الحمايات) فهو **غير
موجود في أي ملف من ملفات الموقع** — يعيش فقط داخل بيئة Edge Function على
خوادم Supabase، ولا يصل إليه المتصفح أبدًا.

**حدود معروفة ما زالت قائمة (بصدق تام):**
- CSP يحتوي `'unsafe-inline'` لسكربتات صغيرة داخل الصفحة (تزامن الحقول)؛
  تشديد إضافي ممكن لاحقًا بنقلها لملفات خارجية + nonce، لكنه يتطلب خادمًا
  ديناميكيًا (غير متاح في استضافة ثابتة بسيطة).
- لا يوجد CAPTCHA على نماذج التسجيل/التواصل (يتطلب مفتاح خدمة خارجية
  مثل hCaptcha/Turnstile لم أُزوَّد بها).
- الخطة المجانية في Supabase محدودة (500 ميغا قاعدة بيانات، 1 غيغا
  تخزين تقريبًا) — كافية للانطلاق، تحتاج ترقية عند نمو حجم الملفات.

## 🌍 اللغات الثلاث

التبديل عبر أزرار AR/FR/EN، يُحفظ في `localStorage`. لإضافة نص جديد:
أضف مفتاحًا في `TRANSLATIONS` بملف `js/i18n.js` لكل لغة، ثم استخدم
`data-i18n="مفتاحك"` (أو `data-i18n-html` إن كان النص يحتوي وسوم HTML
مثل `<strong>`).

## 🌐 النشر

الموقع ملفات ثابتة بالكامل (Vercel/Netlify/GitHub Pages تعمل كلها).
تأكد من:
1. `js/config.js` يحتوي مفاتيحك الحقيقية.
2. Edge Function منشورة (خطوة 2 أعلاه) — وإلا سيفشل كل تحميل.
3. استبدل `WHATSAPP_NUMBER` و`GITHUB_URL` و`LINKEDIN_URL` في `js/config.js`.
4. استبدل النطاق الافتراضي في `robots.txt` و`sitemap.xml` بنطاقك الحقيقي.
